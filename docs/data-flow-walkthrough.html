STAGE 2Where the label comes from

Code: labelling.py:assign_work_categories

Coderaw[cfg.TARGET_COLUMN] = labelling.assign_work_categories(raw).values

Human: The survey never asked "what career category are you?" So the Chapter IV rubric computes it — core courses 30%, GWA 20%, certifications 25%, skills 25%, highest composite wins.

FormulaEvery component is a weighted mean with blanks renormalised away:

                     Σ_i  W_i · x_i
    comp(x, W)  =  ─────────────────────        1[·] = 1 if present, else 0
                   Σ_i  W_i · 1[x_i present]

For each candidate work category c ∈ {Technical, Clerical, Supervisory, Managerial}:

    core_c   =  comp( acad_<domain> ,  profile_c.domains )
    gwa      =  gwa_points                      ← identical for every c
    cert_c   =  comp( cert_<domain> × 100 , profile_c.certs )
    skills_c =  comp( skill × 100 ,  profile_c.skills )

              0.30·core_c + 0.20·gwa + 0.25·cert_c + 0.25·skills_c
    K(c)  =  ──────────────────────────────────────────────────────
                      Σ of the weights whose term is present

    work_category = argmax_c K(c)         margin = K_(1) − K_(2)
R001 — rubric scoresSupervisory  47.89   ← argmax
Clerical     46.91
Managerial   43.58
Technical    42.21

label = Supervisory       margin = 47.89 − 46.91 = 0.98 points
Caveat for Chapter V This label is computed from the same answers the model later reads as inputs. High accuracy proves the model can re-learn your formula — not that it predicts real careers. Report it as a pipeline check. Note also that only two of the four criteria can change the winner: GWA is one number identical across all four categories, so it never breaks a tie, and certifications decide nothing for a student holding none. In practice the label is 55% core courses / 45% skills. Finally, R001's margin is under 1 point — Chapter IV sends exactly this student to the adviser.

STAGE 4Fold 41 courses into 10 shared domains

Code: features.py:add_grade_points

Codecolumns = [c.column for c in cfg.ALL_COURSES if domain in c.domains]
out[f"acad_{domain}"] = points[columns].mean(axis=1, skipna=True)

Human: This is the most important design decision in the pipeline. BSCS students answered 17 courses, BSIT students 24, and they are different courses — so every BSIT column is blank for a BSCS student. If those 41 raw columns went to the model, a tree would learn to read the degree program off the pattern of blanks rather than off the grades.

Instead each course maps into one of 10 domains both programs share. "Data Structures" and BSIT's "Information Management" both land in domains the model understands the same way for everyone. A course may belong to more than one domain.

FormulaLet  C_d = { courses c : d ∈ c.domains  and  p_c is reported }.

                     1
    acad_d   =   ──────────  Σ      p_c                for each of the 10 domains d
                   |C_d|    c ∈ C_d

                        1    10
    core_grade_mean =  ───   Σ   acad_d
                        10  d=1

                        1   10
    variance        =  ───   Σ   ( acad_d − core_grade_mean )²       (population, ddof = 0)
                        10  d=1

    core_grade_std  =  √ variance

Because a student only answers one prospectus, averaging over BOTH programs' columns
for a domain is exactly the mean of whichever set is filled in.

STAGE 5Competency signals — the heart of it

Code: features.py:compute_signal_matrix

Code_SIGNAL_GROUP_WEIGHTS = {"courses": 0.45, "skills": 0.40, "certs": 0.15}

weighted_total   = group_frame.mul(weights, axis=1).sum(axis=1, skipna=True)
available_weight = group_frame.notna().mul(weights, axis=1).sum(axis=1)
score = weighted_total.div(available_weight.where(available_weight > 0))

Human: 11 scores, each 0–100, each blending three kinds of evidence with deliberate weights: grades 45% (registrar-verified, trusted most), ticked skills 40% (self-reported), certificates 15%.

Those last two lines are subtle but critical. If a student skipped a question, only that evidence group drops out and the remaining weights re-normalise. A plain weighted sum would turn one blank cell into a NaN and silently wreck that student's entire report.

FormulaFor each signal s, three evidence groups are formed on a 0–100 scale:

    courses_s  =  mean over  d ∈ s.domains   of   acad_d
    skills_s   =  mean over  k ∈ s.skills    of   (x_k × 100)        x_k ∈ {0,1}
    certs_s    =  mean over  m ∈ s.certs     of   (cert_m × 100)

with group weights   W = { courses 0.45 , skills 0.40 , certs 0.15 }:

                 Σ over present groups g  of   W_g · value_g
    sig_s   =  ───────────────────────────────────────────────     clipped to [0, 100]
                 Σ over present groups g  of   W_g

THE DENOMINATOR IS THE POINT.  An absent group is removed from BOTH sums, so the
remaining weights renormalise. A plain Σ W_g·v_g would propagate one NaN into the
whole score — and from there into every alignment percentage for that student.
R001 — two signals worked in fullsig_programming
   courses  0.45 × acad_programming(57.81)
   skills   0.40 × mean(tech_programming=100, tech_web_mobile_dev=0) = 50.00
   certs    0.15 × 0
   = (0.45×57.81 + 0.40×50.00 + 0.15×0.00) / 1.00  =  46.02

sig_systems_engineering                       ← note the denominator
   courses  0.45 × mean(acad_systems_eng=75.0, acad_foundations=87.5) = 81.25
   skills   0.40 × mean(hard_project_mgmt=0, hard_research_writing=0) =  0.00
            (no cert group is defined for this signal)
   = (0.45×81.25 + 0.40×0.00) / 0.85  =  43.01

The /0.85 is the renormalisation in action — this signal has no certificate component, so the remaining 0.85 of weight absorbs it instead of the score being diluted toward zero.

STAGE 7Expectancy-Value Theory

Code: features.py:add_evt_features

Codeexpectancy = 0.5 * out["gwa_points"] + 0.5 * out["core_grade_mean"]
value      = 0.50*skill_component + 0.30*cert_component + 0.20*type_component
out["evt_motivation"] = (expectancy * value) / 100.0

Human: Chapter III's formula, computed rather than described. Expectancy = "can I do this" (academic record). Value = "is it worth it to me" (skills and credentials actually pursued).

Formula    E  =  0.50 · gwa_points  +  0.50 · core_grade_mean

    V  =  0.50 · S   +   0.30 · C   +   0.20 · T

                1   15
      where S = ───   Σ  x_k × 100      mean of the 15 skill checkboxes, x_k ∈ {0,1}
                15  k=1

                cert_count                        cert_type_count
            C = ────────── × 100            T =  ───────────────── × 100
                     8                                    5

                        E · V
    Motivation(S)  =  ─────────          the ÷100 rescales the product back onto 0–100
                         100

The denominators 8 and 5 are the ceilings: 8 recognised certification domains (Q8)
and 5 credential types (Q9). Holding all of them is the maximum.
R001E = 0.50 × 73.53 + 0.50 × 76.84                      =  75.19
V = 0.50 × 33.33 + 0.30 × 0.00 + 0.20 × 0.00         =  16.67
Motivation = 75.19 × 16.67 / 100                     =  12.53

This is R001's whole story in one number. Because it is a product, not a sum, a near-zero Value collapses the result no matter how good Expectancy is: 75 × 17 → 12.5. He has the ability; he has not yet converted it into credentials. That multiplicative collapse is exactly what EVT predicts, and it is showing up in your data.

STAGE 8Into XGBoost

Code: models.py:build_models

Codexgb_steps = [("impute", SimpleImputer(strategy="median", keep_empty_features=True))]
if use_smote: xgb_steps.append(("smote", AdaptiveSMOTE(random_state=random_state)))
xgb_steps.append(("clf", _boosting_estimator(n_classes, random_state)))

Human: Not bare XGBoost — a three-step pipeline. Blanks filled with the column median, SMOTE balances the classes, then 400 shallow trees (depth 4) each correcting the last.

Why bundle them? If you SMOTE before splitting, synthetic students built from test-set neighbours leak into training and accuracy jumps 5–15 points for free — numbers that will not reproduce. Inside the pipeline, cross_validate refits imputation and SMOTE on each training fold alone. ZeroR deliberately receives no SMOTE: balancing its input would destroy the very floor it measures.

FormulaSTEP A — imputation      x_j ← median_j   for every blank cell in column j

STEP B — adaptive SMOTE  k = min( 5 , n_min − 1 )        n_min = smallest class count
                         k < 1  →  skip resampling, pass data through untouched

STEP C — the regularised boosting objective  (Chen & Guestrin, 2016)

    Obj  =  Σ_i  L( y_i , ŷ_i )  +  Σ_k  Ω( f_k )

                             1
    Ω(f)  =  γ·T   +        ─── λ‖w‖²   +   α‖w‖₁
                             2

    T = number of leaves in tree f,  w = its leaf weights.  Ω is what stops the
    model memorising a single College of Sciences cohort.
Formula — prediction                      400
    margin_c(x)  =      Σ    f_{k,c}(x)         raw additive score per class
                      k=1

                        exp( margin_c )
    P(c | x)   =   ──────────────────────           (softmax, multi:softprob)
                     Σ_j exp( margin_j )

    prediction = argmax_c P(c|x)        confidence = max_c P(c|x)

Then TreeExplainer attributes the decision back to individual features. Units are log-odds, not percentages — "+0.53 pushed the margin for Technical up by 0.53."

FormulaThe Shapley value of feature j — its average marginal contribution over all
orderings of the feature set F  (Lundberg & Lee, 2017):

                      |T|! · ( |F| − |T| − 1 )!
    φ_j  =     Σ     ───────────────────────────  ·  [ f(T ∪ {j}) − f(T) ]
            T ⊆ F\{j}            |F|!

TreeExplainer computes this exactly for tree ensembles in polynomial time.

ADDITIVITY — the property the thesis cites:

    base_c   +   Σ_{j=1}^{m}  φ_{j,c}   =   margin_c(x)

GLOBAL importance, over n explained students:

                       1   n
    I_{j,c}   =       ───  Σ  | φ_{i,j,c} |            Overall_j = mean over c
                       n  i=1

CONTRAST with the runner-up category r:

    δ_j = φ_{j,predicted} − φ_{j,r}        answer = argmax_j δ_j

Read the contributions and the model's reasoning is visible: not ticking Networking and not ticking Research Writing are doing more work than his grades. His 87.50 in Computing Foundations actually pushes him away from Technical — because in this cohort, high foundations grades without technical skills signal a Supervisory/Clerical profile. The model learned that, and SHAP shows it to you.
